How to Add Data

This guide explains the Alonovo data model and the correct order for adding new company data.

Data Model Overview

ModelPurpose
ValueA scoring criterion (e.g., "Corporate Lobbying", "Cage-Free Eggs")
ScoringRuleDefines how to grade a Value — thresholds for metrics, label→grade maps for categories
CompanyA company with ticker, name, sector, website
ClaimAn immutable source fact with provenance — the primary source of truth
CompanyValueSnapshotPre-computed grade per company per value (derived from Claims + ScoringRule)
CompanyBadgeDisplay badges shown on company cards

Order of Operations

When adding data for a new company or a new metric:

Step 1 — Ensure the Company exists

Create the company record in Companies. Give it a uri (company website URL), ticker (if public), name, and sector.

Step 2 — Ensure the Value exists

Check Values for the criterion you need. If it doesn't exist, create it:

  • slug: short machine name (e.g., lobbying_spend)
  • name: human-readable (e.g., "Corporate Lobbying Spend")
  • value_type: metric (numeric thresholds) | label (categorical/certification) | categorical_grade (severity scale)
  • is_fixed: True if users cannot set weight to zero
  • is_disqualifying: True if F on this value = F overall grade
Step 3 — Ensure the ScoringRule exists

Under Values → Scoring Rules, create a rule for the value:

  • version: increment if updating
  • effective_date: date this rule took effect
  • config: JSON thresholds or label map
Step 4 — Add Claims

Add source claims in Claims. Claims are immutable — once created they cannot be edited or deleted.

Required fields:

  • uri: unique identifier for this claim (URN or source URL)
  • subject: the Company URI this claim is about
  • claim_type: the type of data (see Claim Types below)
  • effective_date: the date this data applies to

Depending on claim type, also set:

  • amt + unit: for numeric metrics
  • label: for categorical certifications
  • source_uri: original data source URL
  • how_known: how we learned this
  • statement: human-readable summary
Step 5 — Compute Snapshots

After claims are added, run the management command:

cd /opt/shared/repos/alonovo/backend
source venv/bin/activate
python manage.py compute_snapshots --ticker AAPL

Or recompute via the admin action on the Company list: select companies → Recompute value snapshots.

Step 6 — Verify Badges

Check Company Badges to see if any badges were auto-generated. Add or edit badges manually if needed.

Example: Adding Lobbying Data for Apple

  1. Company: Verify AAPL exists in Companies with uri = https://www.apple.com
  2. Value: Confirm corporate_lobbying Value exists (type: metric)
  3. ScoringRule: Check the rule for corporate_lobbying — config should have thresholds mapping USD amounts to letter grades
  4. Claim: Add a claim:
    • uri: urn:opensecrets:2024:aapl:lobbying
    • subject: https://www.apple.com
    • claim_type: LOBBYING_SPEND
    • amt: 11000000 (or 11.1 with unit = million_usd)
    • unit: USD
    • effective_date: 2024-12-31
    • source_uri: URL from OpenSecrets
    • how_known: reported
  5. Snapshots: Run python manage.py compute_snapshots --ticker AAPL
  6. Verify: Check Apple company page — lobbying card should show the new grade

Importing Data from CSV

For bulk imports, use management commands in backend/core/management/commands/:

  • import_initial_data.py — lobbying, BBFAW, EggTrack, ICE
  • import_esg_data.py — ESG scores from CSV
  • import_peta_data.py — PETA cruelty-free data

Pattern for new imports:

  1. Write findings to prompts/SOURCE_import_instructions.md and get approval
  2. Create a management command following existing patterns
  3. Backup the database first
  4. Test on 5–10 companies before full import
  5. Use Claim.objects.get_or_create() with unique URI to avoid duplicates
